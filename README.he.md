# תבנית לאפליקציות אנדרואיד

אפליקציה חדשה בלי מחשב ובלי Android Studio: Claude כותב את הקוד, GitHub בונה את ה-APK, ומתקינים מלינק קבוע.

## אפליקציה חדשה
1. פותחים את https://github.com/stodio-dev/android-app-template/generate (זה הכפתור **Use this template** בעמוד הריפו),
   נותנים שם, למשל `steps-counter`, ובוחרים **Private**.
2. בריפו החדש: **Settings ← Secrets and variables ← Actions ← New repository secret**
   - שם: `DEBUG_KEYSTORE_B64`
   - ערך: אותו ערך כמו במפות עמדה (מפתח החתימה המשותף שלך).
3. בשיחה עם Claude: נותנים לו את הלינק לריפו החדש ומתארים מה האפליקציה עושה. הוא מריץ
   `tools/new-app.sh` (שם, מזהה, שם קובץ), בונה את המסך הראשון ודוחף. בסשן ייתכן שתתבקש לאשר צירוף של ריפו התבנית:
   זה בשביל יומן הלקחים, שנמצא רק שם (קריאה וכתיבה).
4. אחרי כמה דקות ה-APK מוכן:
   `https://github.com/<owner>/<repo>/releases/download/latest/<שם>.apk`

## מה יש בתבנית
- **בנייה בענן** (`.github/workflows/build.yml`): בדיקות, בנייה, בדיקת חתימה, ושחרור `latest` בכל דחיפה ל-main (דחיפה שמשנה רק מסמכים, `docs/` או קבצי `.md`, לא בונה).
- **מספר גרסה** = מספר ה-commits, כך שכל גרסה מתקינה את עצמה מעל הקודמת.
- **מסך ראשון בעברית** עם מספר גרסה וכפתור "שיתוף יומן תקלות" (כולל דוח קריסה מהפעם הקודמת).
- **תיקיית `core`** ללוגיקה בלי אנדרואיד, עם בדיקות שרצות בענן (`core-tests`).
- **`CLAUDE.md`**: הכללים ש-Claude עובד לפיהם.
- **יומן לקחים** (`docs/lessons/`): תקלות בנייה ושיטות ייעול מכל האפליקציות. המקור הוא ריפו התבנית: Claude קורא ממנו
  וכותב אליו ישירות מכל אפליקציה, ובאפליקציה נשאר רק צילום לקריאה בלבד. `RULES.md` שם קובע איך כותבים רשומה, כדי
  שהתיעוד יהיה אחיד ובלי כפילויות.
- **מאיפה ומתי נוצרה אפליקציה**: `tools/new-app.sh` רושם ב-`gradle.properties` את `template.repo` ו-`template.date`,
  כדי שסשן באפליקציה ידע איפה היומן ואילו תיקוני תבנית כבר יש לה.
